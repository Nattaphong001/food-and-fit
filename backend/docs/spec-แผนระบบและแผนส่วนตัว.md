## 1) หลักการออกแบบ

ระบบใช้หลักการ **คัดลอกทันทีตอนเลือกใช้ (Copy-on-Select)** ในการจัดการข้อมูลแผนการออกกำลังกาย 🔧 Rev3 — เปลี่ยนชื่อจาก "Copy-on-Write" เดิม เพราะไม่ใช่ COW ตามนิยาม CS จริง (COW จะยังอ้างข้อมูลร่วมกันไปก่อน ค่อย copy ตอนเขียนครั้งแรก) ระบบนี้ copy **ทันทีที่กดเลือกใช้แผน** (ดูข้อ 5.1) ไม่ว่าสมาชิกจะแก้ไขจริงหรือไม่ก็ตาม

หลังจาก copy แล้ว สมาชิกแก้ไขสำเนาของตัวเอง (`workout_schedules`) ได้อิสระทีละท่า/ทีละฟิลด์ โดยการแก้ไขแต่ละครั้งเป็นการ `UPDATE`/`INSERT`/`DELETE` ตรงบนสำเนาที่มีอยู่แล้ว **ไม่มีการ copy ซ้ำอีก** 🔧

หลักการนี้ให้ประโยชน์ 3 ประการ:

1. **รักษาความสมบูรณ์ของข้อมูลต้นแบบ** การแก้ไขของสมาชิกคนหนึ่งไม่กระทบสมาชิกคนอื่น เพราะแก้บนสำเนาของตัวเอง (`workout_schedules`, กรอง `mb_id` ทุก endpoint) ไม่แตะ `plan_template_detail` ต้นฉบับที่เป็น master data ร่วมกันเลย
2. **แยกความรับผิดชอบชัดเจน** แอดมินดูแล `workout_plan_template`/`plan_template_detail` ผ่าน route เฉพาะ (`/api/workouts/*`, มี `AdminAuthMiddleware`) สมาชิกไม่มีสิทธิ์แตะตารางนี้โดยตรงเลย
3. **ลดความซับซ้อนของการเขียนโค้ด** endpoint แก้ไข (`CreateWorkoutSchedule`/`UpdateWorkoutSchedule`/`DeleteWorkoutSchedule`) ไม่ต้องรู้ว่าที่มาของแถวเป็นแผนระบบหรือแผนส่วนตัว เพราะทำงานกับ `workout_schedules` ตารางเดียวกันเสมอ

## 2) นิยาม

### 2.1 แผนระบบ (System Plan)

Master data ที่แอดมินสร้างไว้ล่วงหน้า อยู่ใน `workout_plan_template` + `plan_template_detail` **ไม่มีคอลัมน์ `mb_id`** ทุกคนดูร่วมกันชุดเดียว 🔧 (draft แรกสมมติว่าแยกด้วย `mb_id` บนตารางนี้ ไม่ตรงของจริง)

- สมาชิก "เลือกใช้" ผ่าน `POST /member/workout-plans/select` หรือ `POST /member/workout-plans/activate {wpt_id}` — คัดลอกท่าฝึกทั้งหมดจาก `plan_template_detail` ไปที่ `workout_schedules` โดยผูก `wpt_id` (สำเนาของสมาชิกคนนั้น ไม่ใช่แถวร่วม)
- สมาชิกทุกคนเห็นแผนต้นฉบับเหมือนกัน และไม่สามารถแก้/ลบต้นฉบับได้

### 2.2 แผนส่วนตัว (Personal Plan)

ตารางแยกต่างหากชื่อ **`member_workout_plans`** (`mwp_id`, `mb_id`, `mwp_name`, `mwp_days_per_week`, `mwp_created_at`) 🔧 ทางเข้าถึงจาก UI ปัจจุบันมีทางเดียว:

- **สร้างใหม่ทั้งหมด** — `POST /member/workout-plans/mine {name}` สร้างแถว `member_workout_plans` เปล่า แล้วเพิ่มท่าเองทีละท่าผ่าน `POST /member/workout-schedules` (ผูก `mwp_id`)

**คัดลอกจากแผนระบบ (Fork)** — `POST /member/workout-plans/fork {wpt_id}` ยังมีอยู่ใน backend (สร้างแถว `member_workout_plans` ใหม่ + คัดลอกท่าทั้งหมดจาก `plan_template_detail` ผูก `mwp_id` ใหม่ ไม่แตะ/ไม่ลบสำเนา `wpt_id` เดิม) แต่ **ตัดปุ่มเรียกออกจาก UI แล้ว** 🔧 Rev3 (2026-08-16) เก็บ endpoint ไว้เผื่อทำฟีเจอร์ "สร้างแผนจากแม่แบบ" ในอนาคต ตอนนี้ไม่มีทางเรียกจากแอปมือถือ

## 3) ตารางที่เกี่ยวข้อง 🔧 (เขียนใหม่ทั้งหมดให้ตรงของจริง)

| ตาราง | หน้าที่ | คีย์เชื่อม |
|---|---|---|
| `workout_plan_template` | แผนระบบ (master, ไม่มี `mb_id`) | `wpt_id` |
| `plan_template_detail` | ท่าฝึกในแผนระบบ | `wpt_id` |
| `member_workout_plans` | **header** แผนส่วนตัว (ชื่อ + จำนวนวัน/สัปดาห์) | `mb_id`, `mwp_id` |
| `workout_schedules` | ท่าฝึกจริงของสมาชิก ใช้ร่วมทั้ง 2 เส้นทาง | มี `wpt_id` **หรือ** `mwp_id` อย่างใดอย่างหนึ่งต่อแถว (mutually exclusive) |
| `member_profile` | เก็บแผนที่ "ใช้งานอยู่" | `mb_active_wpt_id` / `mb_active_mwp_id` (mutually exclusive) |

**สำคัญ — `workout_schedules` เป็น template รายสัปดาห์ที่วนซ้ำตลอดไป** 🔧 คีย์ด้วย `wsch_day_number` (1=จันทร์…7=อาทิตย์) **ไม่ใช่** `wsch_date` จริง (แม้คอลัมน์นี้จะเป็นชนิด `DATE` — เก็บแค่ "วันที่ copy แผนมา" ไม่ได้ใช้แยกสัปดาห์) ไม่มีแนวคิด "ตารางสัปดาห์นี้" กับ "ตารางสัปดาห์หน้า" เป็นข้อมูลคนละชุด — แก้ท่าของวันจันทร์ 1 ครั้ง มีผลกับวันจันทร์ทุกสัปดาห์ในอนาคตทันที ยืนยันเป็นดีไซน์ตั้งใจของผู้ใช้ระบบ (ไม่มี periodization, progressive overload มาจากผู้ใช้เพิ่มน้ำหนักเองทุกสัปดาห์)

## 5) กระบวนการทำงาน 🔧 (เขียนใหม่ตาม endpoint จริง)

### 5.1 เริ่มต้นใช้แผนระบบ
`POST /member/workout-plans/select {plan_id}` หรือ `POST /member/workout-plans/activate {wpt_id}` (`SelectWorkoutPlan` / `ActivatePlan` ใน `workout_controller.go`)

1. เช็ก **V1-V3** ก่อน copy ทุกครั้ง (`validateTemplateComplete`) — แผนต้องมีวันฝึก ≥1 วัน, แต่ละวันมีท่า ≥1 ท่า, จำนวนวันตรง `wpt_days_per_week`
2. ถ้าสมาชิกเคย copy แผนนี้แล้ว (มีแถว `workout_schedules` ผูก `wpt_id` นี้อยู่แล้ว) → ใช้ของเดิม ไม่ copy ทับ (idempotent)
3. ถ้ายังไม่เคย → copy ท่าทั้งหมดจาก `plan_template_detail` ไปที่ `workout_schedules` (map `ptd_day_number` → `wsch_day_number` ด้วย `toWeekday()`)
4. ตั้ง `member_profile.mb_active_wpt_id` = แผนนี้ (`mb_active_mwp_id` = NULL)

### 5.2 คัดลอกแผนระบบเป็นแผนส่วนตัว (Fork) — ⚙️ backend เท่านั้น ไม่มีปุ่มใน UI แล้ว 🔧 Rev3 (2026-08-16)
`POST /member/workout-plans/fork {wpt_id}` (`ForkWorkoutPlan`) — endpoint ยังทำงานได้ปกติ เก็บไว้เผื่อทำฟีเจอร์ "สร้างแผนจากแม่แบบ" ในอนาคต แต่ไม่มีทางเรียกจากแอปมือถือตอนนี้แล้ว (ตัดปุ่มออกจาก `weight_training_schedule_view.dart`)

1. เช็ก V1-V3 เหมือนข้อ 5.1
2. สร้างแถวใหม่ใน `member_workout_plans` (`mb_id` ของสมาชิก, ชื่อ `"<ชื่อแผนระบบ> (ของฉัน)"`, `mwp_days_per_week` = `wpt_days_per_week` เดิม)
3. copy ท่าทั้งหมดจาก `plan_template_detail` ไปที่ `workout_schedules` ผูก `mwp_id` ใหม่ (ใช้ `toWeekday()` เดียวกับข้อ 5.1 เป๊ะ)
4. **ไม่ auto-activate** และ **ไม่แตะ/ไม่ลบสำเนา `wpt_id` เดิม** — ผลลัพธ์คือมี 2 แผนในลิสต์ "แผนของฉัน" พร้อมกัน สมาชิกเลือก activate แผนไหนก็ได้ทีหลัง

### 5.3 สร้างแผนส่วนตัวใหม่ทั้งหมด (เปล่า)
`POST /member/workout-plans/mine {name}` (`CreatePersonalPlan`) → สร้าง `member_workout_plans` เปล่า แล้วเพิ่มท่าเองทีละท่าผ่าน `POST /member/workout-schedules {mwp_id, day_number, wet_id, ...}`

### 5.4 การแก้ไขแผน (ทั้งแผนระบบที่ copy มาแล้ว และแผนส่วนตัว) 🔧 จุดที่ดราฟต์แรกเข้าใจผิดมากที่สุด
`POST/PATCH/DELETE /member/workout-schedules[/:id]` (`CreateWorkoutSchedule`/`UpdateWorkoutSchedule`/`DeleteWorkoutSchedule`)

**Copy-on-Write ไม่ได้เกิดตอนนี้** — ไม่มี "copy ใหม่เมื่อกดแก้ครั้งแรก" ทุก endpoint แก้ไข **ตรง** บนสำเนาที่มีอยู่แล้วใน `workout_schedules` (สร้างไว้แล้วตั้งแต่ข้อ 5.1/5.2/5.3) กรอง `wsch_id`/`mb_id` เท่านั้น ไม่แตะ `plan_template_detail` ต้นฉบับไม่ว่ากรณีใด — เพราะแถวที่แก้เป็นสำเนาส่วนตัวของสมาชิกอยู่แล้วตั้งแต่ต้น (มี `mb_id` กำกับ) การแก้จึงไม่กระทบสมาชิกคนอื่นหรือแม่แบบระบบโดยธรรมชาติของสถาปัตยกรรม ไม่จำเป็นต้องมีกลไก copy-on-write เพิ่มเติมตรงจุดนี้

### 5.5 การเปลี่ยนไปแผนอื่น (active)
`POST /member/workout-plans/activate {wpt_id | mwp_id}` (`ActivatePlan`) — สลับ `member_profile.mb_active_wpt_id`/`mb_active_mwp_id` เท่านั้น ไม่ลบข้อมูลแผนที่เลิก active (ยังอยู่ในลิสต์ "แผนของฉัน" เรียก activate กลับมาใช้ใหม่ได้)

### 5.6 ~~การสร้างตารางของสัปดาห์ถัดไป~~ 🔧 ตัดออก — ไม่มีจริง
ดราฟต์แรกสมมติว่ามีกลไก generate ตาราง `workout_schedules` ใหม่ทุกสัปดาห์จากสัปดาห์ล่าสุด **ไม่มีอยู่จริง และไม่ควรมีตามดีไซน์** — ดูเหตุผลในข้อ 3: `workout_schedules` เป็น template ที่ผูกกับ "วันในสัปดาห์" (`wsch_day_number`) แบบถาวร ไม่ใช่ข้อมูลรายสัปดาห์ที่ต้อง gen ใหม่ทุกรอบ

### 5.7 คืนค่าเดิม (Reset) 🔧 ใหม่ — เพิ่มปุ่มใน UI แล้ว (2026-08-16)
`POST /member/workout-plans/reset {plan_id}` หรือ `{mwp_id}` (`ResetWorkoutPlan`) — เรียกได้จากหน้าตารางฝึก (`weight_training_schedule_view.dart`) ไม่ต้องเป็นแผน active ก่อน (ต่างจาก `resetActivePlan()` ฝั่ง Flutter ที่ผูกกับแผน active ใน local storage เท่านั้น ยังใช้อยู่ในหน้า `workout_view.dart`)

1. แผนระบบ (`plan_id`/`wpt_id`) — เช็ก V1-V3 ก่อน แล้วลบ `workout_schedules` ของสมาชิกที่ผูก `wpt_id` นี้ทั้งหมด แล้ว copy ท่าจาก `plan_template_detail` ใหม่ทับ (เหมือนข้อ 5.1 ตอนยังไม่เคย copy)
2. แผนส่วนตัว (`mwp_id`) — ลบ `workout_schedules` ที่ผูก `mwp_id` นี้ทั้งหมด **ไม่ copy ท่าใหม่ให้** (ไม่มีแม่แบบให้อ้างอิง) แผนกลับไปว่างเปล่าเหมือนตอนสร้างใหม่

**สำคัญ** — ตัดปุ่ม Fork ออกจาก UI แล้ว (ข้อ 5.2) จึงไม่มีสำเนาสำรองให้กู้ถ้าลบท่าผิดพลาด ปุ่มคืนค่าเดิมนี้เป็นทางเดียวที่กู้แผนระบบกลับสภาพเดิมได้โดยไม่ต้องลบทั้งแผนแล้วเลือกใหม่

## 7) การแสดงผลหน้าจอที่เกี่ยวข้อง 🔧 ปรับให้ตรงชื่อไฟล์/พฤติกรรมจริง

### 7.1 หน้า "แผนของฉัน" (`lib/views/member/workout/my_workout_plans_view.dart`)
รวมลิสต์แผนระบบที่เคย select มา (ไม่มีทาง fork แล้ว — ดูข้อ 5.2) + แผนส่วนตัวทั้งหมดในหน้าเดียว แต่ละการ์ดมีปุ่ม "ใช้แผนนี้" (activate) และไอคอนลบ — เฉพาะแผนส่วนตัวมีไอคอนแก้ชื่อเพิ่ม (แผนระบบที่ปรับแต่งแล้วยังแก้ชื่อไม่ได้ ดู Rev3 ข้อ 5) สีของการ์ดต่างกัน 3 แบบ: แผนระบบเดิม (เขียว) / แผนระบบที่ถูกปรับแต่งแล้ว (ส้ม, ตรวจจากการเทียบจำนวนวัน/ท่ากับต้นฉบับ) / แผนส่วนตัว (ฟ้า)

ป้ายบอก "X วัน / สัปดาห์" ใต้ชื่อแผน 🔧 Rev3 แก้ให้คำนวณจากจำนวนวันที่มีท่าฝึกจริงทั้งแผนระบบและแผนส่วนตัว (เดิมแผนส่วนตัวโชว์ป้าย "แผนส่วนตัว (จ-อา)" ซ้ำกับป้ายประเภทแผนที่ขึ้น "แผนส่วนตัว" อยู่แล้ว)

### 7.2 หน้า "ตารางฝึก" (`lib/views/member/workout/weight_training_schedule_view.dart`)
แสดง/แก้ท่าฝึกรายวันของแผนที่เลือก มีปุ่ม **"คืนค่าเดิม"** (ไอคอน restore สีแดง มุมขวาบนของ header) 🔧 Rev3 (2026-08-16) แทนที่ปุ่ม "คัดลอกเป็นแผนของฉัน" เดิมที่ตัดออกแล้ว — แสดงทุกแผนทั้งระบบและส่วนตัว กดแล้วเปิด dialog ยืนยัน (ข้อความต่างกันตามประเภทแผน) ก่อนเรียก `POST /member/workout-plans/reset` (ดูข้อ 5.7)
