## 1. หลักการ 5 ข้อ

| # | หลักการ | ความหมายในทางปฏิบัติ |
|---|---|---|
| 1 | **เทาคือสีหลัก** | สีเทาและขาวควรครองพื้นที่ประมาณ 80% ของหน้าจอ สีอื่นเป็นส่วนเน้นเท่านั้น |
| 2 | **เขียวเต็มใช้ได้จุดเดียวต่อหน้า** | ปุ่มพื้นเขียวมีได้ 1 ปุ่มต่อหน้าจอ ที่เหลือเป็นปุ่มเส้นขอบ |
| 3 | **สีต้องสื่อความหมาย** | ห้ามใช้สีเพื่อความสวยงาม ไอคอนที่ไม่ได้บอกสถานะต้องเป็นสีเทา |
| 4 | **สัดส่วนมากกว่า = สีเข้มกว่า** | ในกราฟทุกชนิด ส่วนที่มีค่ามากที่สุดต้องเข้มที่สุดเสมอ |
| 5 | **หน้าที่ทำงานเหมือนกันต้องหน้าตาเหมือนกัน** | หน้าจัดการข้อมูลพื้นฐานทั้ง 10 หน้า ต้องใช้โครงเดียวกันทุกหน้า |

## 2. โครงไฟล์ของ Design System

```
lib/core/
├── constants/
│   ├── layout_breakpoints.dart  ← จุดเปลี่ยนขนาดจอ (AppBreakpoints, LayoutTier) เท่านั้น
│   └── api_config.dart
├── theme/
│   └── theme.dart               ← ค่าสี ตัวอักษร ระยะห่าง ความโค้งมุม ทั้งหมด + ประกอบเป็น ThemeData
└── widgets/                     ← คอมโพเนนต์กลาง
```

**กฎการแบ่งไฟล์:**

- `theme.dart` — ไฟล์เดียวที่ประกาศค่าสี ตัวอักษร ระยะห่าง และความโค้งมุมของทั้งระบบ
  (`AppColors`, `AppTextStyles`, `AppSpacing`, `AppRadius`, `AppBmiPalette`, `AppTheme`)
  **ห้ามสร้างไฟล์ token แยกเพิ่มอีก** เพราะจะทำให้ค่าซ้ำและไม่ตรงกัน (เคยเกิดมาแล้วกับ
  `app_colors.dart` / `app_text_styles.dart` เดิม — ถูกรวมเข้า `theme.dart` แล้ว)
- `layout_breakpoints.dart` — ข้อยกเว้นเดียว เก็บ `AppBreakpoints`/`LayoutTier` เพราะเป็นค่ากำหนด
  พฤติกรรม layout ไม่ใช่สี/ตัวอักษร/ระยะห่าง/ความโค้งมุม
- **ไฟล์หน้าจอทุกไฟล์ import ธีมด้วยบรรทัดเดียว:**
  `import 'package:myapp_admin/core/theme/theme.dart';`
  (เพิ่ม `import '.../constants/layout_breakpoints.dart';` เป็นบรรทัดที่สองได้เฉพาะไฟล์ที่ใช้ breakpoint)

**ห้ามเขียนแบบนี้ในไฟล์หน้าจอเด็ดขาด:**

```dart
// ผิด
Container(color: Color(0xFF10B981))
Text('...', style: TextStyle(fontSize: 28, fontWeight: FontWeight.w600))
padding: EdgeInsets.all(20)

// ถูก
Container(color: AppColors.primary)
Text('...', style: AppTextStyles.kpiValue)
padding: AppSpacing.cardPadding
```

### 3.3 สีสถานะ

ใช้ได้เมื่อสื่อความหมายเท่านั้น ทุกตัวมีคู่ พื้นอ่อน + ตัวอักษรเข้ม

| Token | สีหลัก | พื้นอ่อน | สีตัวอักษรบนพื้นอ่อน (`*Text`) | ความหมาย |
|---|---|---|---|---|
| success | `#10B981` | `#ECFDF5` | `#059669` | บัญชีปกติ, สมส่วน, บันทึกสำเร็จ |
| warning | `#F59E0B` | `#FFFBEB` | `#C2410C` | รอยืนยันตัวตน, น้ำหนักเกิน |
| danger | `#EF4444` | `#FEF2F2` | `#DC2626` | ระงับการใช้งาน, ลบข้อมูล, โรคอ้วน |
| info | `#3B82F6` | `#EFF6FF` | `#2563EB` | ข้อมูลทั่วไป, ลิงก์, ผอมเกินไป |

ค่า `*Text` จูน contrast ให้ผ่าน WCAG AA (≥ 4.5:1) ไว้แล้ว ทั้งกรณีเป็นตัวอักษรบนพื้นอ่อน และกรณีใช้สีหลักเป็นพื้นเข้มแล้วสลับ `*Text` ไปคุมโทน (เช่น `top_flash`)

**กฎเหล็ก:** ห้ามใช้ตัวอักษรสีดำหรือขาวบนพื้นสีอ่อน ต้องใช้ `*Text` จากตระกูลเดียวกันเสมอ ห้ามใช้สีหลัก (`success`/`warning`/`danger`/`info`) เป็นสีตัวอักษรบนพื้นอ่อนโดยตรง

## 4. ตัวอักษร (Typography)

ใช้เพียง **6 สไตล์ 2 น้ำหนัก** ห้ามสร้างขนาดใหม่นอกตารางนี้

| Token | ขนาด / น้ำหนัก | ใช้กับ |
|---|---|---|
| `kpiValue` | 28 / 600 | ตัวเลขในการ์ดสรุป |
| `kpiUnit` | 14 / 400 | หน่วยต่อท้ายตัวเลข เช่น "คน" "kcal" |
| `pageTitle` | 20 / 600 | ชื่อหน้าใน header |
| `cardTitle` | 16 / 600 | หัวข้อการ์ด |
| `body` | 14 / 400 | เนื้อหา, ข้อมูลในตาราง, ป้ายปุ่ม |
| `tableHeader` | 13 / 600 | หัวคอลัมน์ตาราง |
| `kpiLabel` / `caption` | 12–13 / 400 | ป้ายกำกับ, แกนกราฟ, ข้อความประกอบ |
| `sidebarSection` | 11 / 600 | หัวข้อกลุ่มเมนู (letter-spacing 0.5) |

**กฎ:**
- น้ำหนักใช้ได้แค่ `w400` และ `w600` — ห้ามใช้ `w500` หรือ `w700`
- ตัวเลขทุกตัวที่แสดงต้องผ่านการจัดรูปแบบ เช่น `NumberFormat('#,##0')` ห้ามโชว์ทศนิยมลอย ๆ
- ค่าพลังงานปัดเป็นจำนวนเต็ม, ค่า BMI ทศนิยม 1 ตำแหน่ง, เปอร์เซ็นต์ทศนิยม 0–1 ตำแหน่ง

## 5. ระยะห่างและความโค้งมุม

ยึดทวีคูณของ 4 เสมอ

| Token | ค่า | ใช้กับ |
|---|---|---|
| `AppSpacing.xs` | 4 | ระยะระหว่างบรรทัดในการ์ด |
| `AppSpacing.sm` | 8 | ระยะระหว่างไอคอนกับข้อความ |
| `AppSpacing.md` | 16 | **ระยะระหว่างการ์ดในแถวเดียวกัน** |

| `AppSpacing.xl` | 32 | ระยะแยกกลุ่มเนื้อหาใหญ่ |
| `AppSpacing.cardPadding` | 20 รอบด้าน | ระยะขอบในของการ์ด |

| Token | ค่า | ใช้กับ |
|---|---|---|
| `AppRadius.sm` | 6 | ป้ายสถานะ, ชิป |
| `AppRadius.md` | 8 | ปุ่ม, ช่องกรอกข้อมูล |
| `AppRadius.lg` | 12 | การ์ด, ตาราง, Dialog |

## 6. เส้นขอบ เงา และพื้นผิว

- การ์ดทุกใบ: พื้น `surface` + เส้นขอบ 1 px `border` + มุม 12 + **`elevation: 0`**
- **ห้ามใส่เงาให้การ์ด** เพราะแดชบอร์ดที่การ์ดทุกใบมีเงาจะดูรกและแยกลำดับชั้นไม่ออก
- เงาใช้ได้เฉพาะกับสิ่งที่ลอยเหนือหน้าจริง ๆ เท่านั้น: `Dropdown`, `Dialog`, `Drawer`, `top_flash`
- พื้นหลังหน้าต้องเป็น `background` (`#F9FAFB`) ไม่ใช่สีขาว มิฉะนั้นการ์ดขาวจะไม่ลอยออกจากพื้น

## 7. ปุ่มและลำดับความสำคัญ

| ระดับ | Widget | หน้าตา | ใช้กี่ปุ่มต่อหน้า |
|---|---|---|---|
| หลัก | `ElevatedButton` | พื้นเขียว `primary` ตัวอักษรขาว | **1 ปุ่ม** |
| รอง | `OutlinedButton` | พื้นขาว เส้นขอบเทา ตัวอักษร `textSecondary` | ไม่จำกัด |
| ข้อความ | `TextButton` | ไม่มีพื้น ตัวอักษร `primaryDark` | ไม่จำกัด |
| อันตราย | `OutlinedButton` + สี `danger` | เส้นขอบและตัวอักษรสีแดง | เท่าที่จำเป็น |

**การเลือกปุ่มหลักของแต่ละหน้า:**

| หน้า | ปุ่มหลักคือ |
|---|---|
| แดชบอร์ด | ไม่มี (หน้านี้เป็นหน้าอ่านอย่างเดียว) |
| จัดการข้อมูลพื้นฐาน | "เพิ่มข้อมูล" |
| รายงาน | "ส่งออก PDF" |
| Dialog ยืนยัน | ปุ่มยืนยันการกระทำ |

⚠️ ปุ่มลบต้อง **ไม่ใช่** พื้นแดงทึบ ให้ใช้เส้นขอบแดง แล้วให้ `app_confirm_dialog` เป็นด่านยืนยันแทน

## 8. ป้ายสถานะ (Badge)

ไม่มี helper กลาง — แต่ละหน้าประกาศฟังก์ชันแปลค่า → (label, color) ของตัวเอง
(เช่น `_statusLabel`/`_statusColor` ใน `manage_members_view.dart`,
`manage_admins_view.dart`, `_getDiffText`/`_getDiffColor` ใน
`manage_weight_exercises_view.dart`) มี 2 รูปแบบภาพ ใช้ตามชนิดข้อมูล:

**ป้ายสถานะ (active/inactive) — pill เต็ม:**
พื้นสี alpha 0.12 เต็มรูป + ตัวอักษรสีเข้มตระกูลเดียวกัน + มุมโค้งเต็ม
(`BorderRadius.circular(999)`) + padding แนวนอน 10 แนวตั้ง 4 + ขนาดตัวอักษร 11.5
น้ำหนัก w700

| บริบท | ข้อความ | สี |
|---|---|---|
| สถานะบัญชีแอดมิน (`sys_status`) | ใช้งานอยู่ / ปิดใช้งาน | เขียว / ส้ม |

**ป้ายระดับ (difficulty/zone) — chip กรอบบาง:**
พื้นสี alpha 0.06-0.1 + กรอบสีเดียวกับตัวอักษร (width 0.5) + มุมโค้ง 6-12 +
ขนาดตัวอักษร 11-13 น้ำหนัก w600

| บริบท | ค่า | สี |
|---|---|---|
| ระดับความยาก (`wpt_difficulty` / exercise diff) | ง่าย / ปานกลาง / ยาก / ไม่ระบุ | เขียว / ส้ม / แดง / เทา |
| ส่วนของกล้ามเนื้อ (`mug_zone`) | บน / ล่าง / แกนกลาง | ใช้เทาทั้งหมด (ไม่ได้บอกความรุนแรง) |
| ระดับความหนักของการฝึก (`wtrs_intensity_level`) | เบา / กลาง / หนัก | เทา / ส้ม / แดง |

⚠️ แถว `wtrs_intensity_level` ยังไม่มีหน้าจอ admin ที่ใช้งานจริง — สงวนไว้เผื่ออนาคต
ห้ามเดาโครงสร้างตอนเริ่มทำ ให้ตรวจ Data Dictionary บทที่ 4 ก่อนเสมอ

## 9. คอมโพเนนต์กลาง

ทุกหน้าต้องประกอบจากคอมโพเนนต์ใน `lib/core/widgets/` เท่านั้น ห้ามเขียน UI ซ้ำในไฟล์หน้าจอ

### 9.1 คอมโพเนนต์ที่มีอยู่แล้ว

| ไฟล์ | หน้าที่ | ข้อกำหนด |

## 10. กราฟ (Chart Rules)

ใช้แพ็กเกจ `fl_chart` ทั้งระบบ

### 10.1 การเลือกชนิดกราฟ

| ข้อมูล | ใช้กราฟ | เหตุผล |
|---|---|---|
| แนวโน้มตามเวลา | เส้น (Line) | เห็นทิศทางชัด |
| เปรียบเทียบตามช่วงเวลา | แท่งแนวตั้ง (Bar) | |
| **จัดอันดับที่ชื่อยาว** | **แท่งแนวนอน** | ชื่ออาหารไทยยาว วางแนวตั้งแล้วป้ายเอียงอ่านไม่ออก |
| สัดส่วนไม่เกิน 4 กลุ่ม | โดนัท | เกิน 4 กลุ่มให้ใช้แท่งแนวนอนแทน |
| ค่าที่แยกองค์ประกอบได้ | แท่งซ้อน (Stacked) | เช่น Baseline + Exercise |

### 10.2 กฎการใช้สีในกราฟ

1. **ส่วนที่มากกว่าต้องเข้มกว่าเสมอ** — โดนัทที่ส่วน 66% เป็นเทาและส่วน 34% เป็นเขียวสด จะทำให้อ่านลำดับความสำคัญผิดทันที
2. ในกราฟชุดเดียวกัน ใช้เฉดจากตระกูลสีเดียวกัน (`primary` + `primaryLight`) ไม่ใช่คนละสี
3. ลิสต์จัดอันดับใช้สีเดียวทั้งคอลัมน์ แล้วสื่อสัดส่วนด้วยความยาวแถบ ไม่ใช่ด้วยสี
4. เส้นกริดใช้ `border` เส้นบาง 1 px และแสดงเฉพาะแนวนอน

### 10.3 แกนและตัวเลข

- ค่าสูงสุดของแกน Y ต้องปัดเป็นเลขกลม (25,000 ไม่ใช่ 25,175)
- เส้นกริดแบ่งเท่ากัน 4–5 ช่วง
- ป้ายแกนใช้ `caption` (12 px `textMuted`)

### 10.4 กรณีสเกลต่างกันมาก

เมื่อชุดข้อมูลสองชุดต่างกันเกิน 5 เท่า (เช่น พลังงานรับเข้าหลักหมื่น เทียบกับพลังงานออกกำลังกายหลักพัน) **ห้ามวางเป็นแท่งคู่บนแกนเดียว** เพราะแท่งเล็กจะมองไม่เห็น ให้เลือกทางใดทางหนึ่ง:

1. กราฟผสม: ชุดใหญ่เป็นแท่ง ชุดเล็กเป็นเส้นบนแกน Y ที่สอง
2. เปลี่ยนเป็นกราฟ **สมดุลพลังงานสุทธิ** แสดงแท่งขึ้น/ลงจากเส้นศูนย์

## 11. สถานะของหน้าจอ

ทุกกราฟ ทุกตาราง ทุกลิสต์ ต้องรองรับครบ 4 สถานะผ่าน `admin_list_state.dart`

| สถานะ | การแสดงผล |
|---|---|
| กำลังโหลด | โครงร่างสีเทา (Skeleton) ตามรูปทรงเนื้อหาจริง **ไม่ใช่วงกลมหมุนกลางจอ** — ใช้ `AppColors.skeletonBase` เป็นพื้นกล่อง และ `AppColors.skeletonHighlight` เป็นแถบ shimmer ที่กวาดผ่าน ความเร็วประมาณ 1.5 วินาทีต่อรอบ |
| ไม่มีข้อมูล | ไอคอน `textDisabled` + "ยังไม่มีข้อมูลในช่วงเวลาที่เลือก" + ปุ่มแนะนำการกระทำถัดไป |
| ผิดพลาด | ไอคอนสี `danger` + บอกว่าเกิดอะไรและทำอย่างไรต่อ + ปุ่ม "ลองใหม่" |
| มีข้อมูล | แสดงผลปกติ |

**ข้อความผิดพลาดต้องบอกวิธีแก้ ไม่ใช่ขอโทษ**

```
ผิด : เกิดข้อผิดพลาด กรุณาลองใหม่อีกครั้ง
ถูก : เชื่อมต่อเซิร์ฟเวอร์ไม่สำเร็จ ตรวจสอบอินเทอร์เน็ตแล้วกดลองใหม่
```

⚠️ ข้อนี้สำคัญมากตอนสอบ เพราะผู้ทดสอบมักเลือกช่วงวันที่ที่ยังไม่มีข้อมูล ถ้าจอว่างเปล่าจะถูกมองว่าระบบไม่สมบูรณ์

### 12.1 โครงร่วม (`admin_shell_view.dart`)

```

│ 240–260  │                                      │

│          │                                      │

```

**Sidebar:** พื้นขาว, เส้นขอบขวา 1 px, หัวข้อกลุ่มใช้ `sidebarSection`, เมนูย่อยเยื้องเข้า 8 px, เมนูที่เลือกใช้พื้น `primarySurface` + ตัวอักษร `primaryDark` + ขีดซ้าย 3 px

### 12.2 แม่แบบหน้าจัดการข้อมูล (ใช้กับทั้ง 10 หน้า)

```
admin_page_header      ชื่อหน้า + จำนวนรายการ + ปุ่ม "เพิ่มข้อมูล"
admin_filter_bar       ค้นหา + ชิปกรอง

admin_pagination_bar   แบ่งหน้า
```

ทุกตารางในกลุ่มนี้ควรมีคอลัมน์ **"ยอดใช้งาน"** (นับจาก Foreign Key) เพื่อบอกแอดมินว่ารายการไหนลบได้

### 12.3 แม่แบบหน้าแดชบอร์ด

```
แถว 1 : admin_kpi_card × 4                    (Row + Expanded, gap 16)
แถว 2 : admin_chart_card (flex 8) + admin_chart_card (flex 4)
แถว 3 : การ์ดความเคลื่อนไหวล่าสุด (เต็มความกว้าง)
```

⚠️ **หน้าแดชบอร์ดห้ามมีตัวเลือกช่วงเวลา** ช่วงเวลาตายตัวที่ 7 หรือ 14 วันล่าสุด — นี่คือสิ่งที่แยกหน้านี้ออกจากหน้ารายงาน

### 12.4 แม่แบบหน้ารายงาน

```
admin_page_header      "รายงานระบบ" + ปุ่ม "ส่งออก PDF"
admin_filter_bar       วัน / สัปดาห์ / เดือน / กำหนดเอง + ข้อความช่วงที่เลือก
TabBar                 3 แท็บ
  ├ พฤติกรรมการใช้งาน
  ├ การใช้งานคลังข้อมูล
  └ สถิติสุขภาพภาพรวม
```

ในแต่ละแท็บใช้ลำดับ **การ์ดสรุป → กราฟ → ตาราง** เสมอ

### 12.5 กฎการจัดแถว

- การ์ดในแถวเดียวกันต้องสูงเท่ากัน ใช้ `CrossAxisAlignment.stretch` ใน `Row`
- ห้ามใส่การ์ดสรุปเกิน 4 ใบต่อแถว หากมี 6 ตัวชี้วัดแสดงว่ากำลังยัดแดชบอร์ดให้เป็นหน้ารายงาน
- ตัวเลขที่แสดงในการ์ดสรุปแล้ว ห้ามแสดงซ้ำในกล่องใต้กราฟ

## 15. ข้อกำหนดที่ผูกกับเอกสารโปรเจกต์

ค่าเหล่านี้ห้ามเปลี่ยนโดยพลการ เพราะผูกกับตัวเลขในเล่ม

| เรื่อง | ข้อกำหนด | อ้างอิง |
|---|---|---|
| เกณฑ์ BMI | 18.5 / 23.0 / 25.0 (เอเชีย-แปซิฟิก) | บทที่ 2 ข้อ 2.1.4.1 |
| Baseline Expenditure | BMR × 1.2 เสมอ | บทที่ 2 ข้อ 2.1.4.6 |
| Total Daily Energy Output | Baseline + Σ Exercise Burn | บทที่ 2 ข้อ 2.1.4.6 |
| ตัวกรองรายงาน | ต้องมี รายวัน / รายสัปดาห์ / รายเดือน ครบ | บทที่ 3 ข้อ 3.3.4 |
| รูปแบบแสดงผลรายงาน | ต้องมีทั้งกราฟและตาราง | บทที่ 3 ข้อ 3.3.4 |
| ค่า Training Volume / 1RM | คำนวณแสดงผลบนหน้าจอ **ไม่บันทึกลงฐานข้อมูล** | บทที่ 2 ข้อ 2.1.4.13 |

**การแสดงค่าพลังงานต้องแยกป้ายให้ชัด** ห้ามแสดงเป็นตัวเลขก้อนเดียวโดยไม่บอกว่ารวมอะไร:

| ป้ายที่แสดง | สูตร |
|---|---|
| พลังงานพื้นฐาน (Baseline Expenditure) | BMR × 1.2 |
| พลังงานจากการออกกำลังกาย (Exercise Burn) | Σ Cardio + Σ Weight Training |
| พลังงานใช้ออกรวม (Total Daily Energy Output) | ผลรวมทั้งสอง |

**ข้อมูลสุขภาพต้องแสดงเป็นค่ารวมเท่านั้น** หน้าสถิติสุขภาพต้องมีแถบแจ้งเตือนว่า "ข้อมูลในหน้านี้แสดงเป็นค่าเฉลี่ยรวมของสมาชิกทั้งระบบ ไม่สามารถระบุตัวบุคคลได้"
