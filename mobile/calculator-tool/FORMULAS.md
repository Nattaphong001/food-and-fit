## [0] ข้อมูลพื้นฐานร่างกาย (Foundation)

**ที่มา:** `backend/services/calculator.go` ฟังก์ชัน `CalculateGoals` — จุดเดียวที่คำนวณ 4 ค่านี้ เรียกจาก `UpdateBodyStats`/`EditProfile`

### BMI (ดัชนีมวลกาย)
```
BMI = น้ำหนัก(kg) / ส่วนสูง(m)²
```
ตัวอย่าง: 70 / (1.75×1.75) = 70/3.0625 = **22.86** (ปัด 2 ตำแหน่ง) → เกณฑ์เอเชีย-แปซิฟิก: 18.5–22.9 = **สมส่วน**

### BMR (Basal Metabolic Rate) — Mifflin-St Jeor
```
ชาย : BMR = (10×kg) + (6.25×cm) − (5×อายุ) + 5
หญิง: BMR = (10×kg) + (6.25×cm) − (5×อายุ) − 161
```
ตัวอย่าง (ชาย): (10×70)+(6.25×175)−(5×30)+5 = 700+1093.75−150+5 = **1648.75 kcal/วัน**

### TDEE (Total Daily Energy Expenditure)
```
TDEE = BMR × Activity Factor
```
Activity Factor มีได้แค่ 5 ค่า: **1.2 / 1.375 / 1.55 / 1.725 / 1.9** (ห้ามเป็นค่ากลางๆ)
ตัวอย่าง: 1648.75 × 1.55 = **2555.56 kcal/วัน**

**ปัดเศษ:** BMI/BMR/TDEE ปัด 2 ตำแหน่งเสมอ (`math.Round(x*100)/100`)

## [A] พลังงานที่กินเข้า (Energy In)

### A1. Target Calories

**ที่มา:** `calculator.go:54-64` (ต่อจาก `CalculateGoals`)

| goal_type | สูตร | เงื่อนไขนิรภัย |
|---|---|---|
| 1 = ลดน้ำหนัก | TDEE − (TDEE×20%) | ถ้า < BMR → ใช้ BMR แทน (**ห้ามต่ำกว่า BMR**) |
| 2 = เพิ่มน้ำหนัก | TDEE + (TDEE×15%) | ไม่มี clamp |
| 3 = รักษาน้ำหนัก | = TDEE | ไม่มี clamp |

ตัวอย่าง (goal=1): 2555.56 − (2555.56×0.20) = 2555.56−511.11 = **2044.45 kcal** (>BMR 1648.75 ไม่ชน clamp)

ตัวอย่าง clamp ทำงานจริง (คนละเคส): BMR=1400, TDEE=1680 → Target ดิบ=1680−336=1344 < 1400 → ใช้ **1400** แทน

### A2. สัดส่วนสารอาหาร (Macro grams)

**⚠️ ที่มา:** implement ที่ **Dart เท่านั้น** `mobile/lib/views/member/nutrition/nutrition_view.dart:100-111` — ไม่มีใน backend

| goal_type | โปรตีน | คาร์บ | ไขมัน |

| 1 ลดน้ำหนัก | 40% | 35% | 25% |
| 2 เพิ่มน้ำหนัก | 30% | 50% | 20% |
| 3 รักษาน้ำหนัก | 20% | 50% | 30% |

```
โปรตีน(g) = (Target × %โปรตีน) / 4     (โปรตีน 1g = 4 kcal)
คาร์บ(g)   = (Target × %คาร์บ)   / 4     (คาร์บ 1g = 4 kcal)
```

### A3. พลังงานที่กินจริงวันนี้ (Energy In actual)

**ที่มา:** `SUM(dntt_total_calories)` ฯลฯ ใน `analytics_controller.go:44-47` (`GetDailyAnalytics`)
คูณจำนวนหน่วยที่ `nutrition_controller.go:461-464` (`AddDailyNutrition`) / `:561-564` (`UpdateDailyNutrition`)

```
ค่าต่อแถว = ค่าสารอาหารต่อ 1 หน่วย × จำนวนหน่วยที่กิน      — ครบทั้ง 4 ค่าพร้อมกัน
  dntt_total_calories = ntt_calories × dntt_quantity
  dntt_total_protein  = ntt_protein  × dntt_quantity
  dntt_total_carb     = ntt_carbs    × dntt_quantity
  dntt_total_fat      = ntt_fat      × dntt_quantity

Energy In = SUM(dntt_total_calories ทุกแถวของวันนั้น) — หลายแถวต่อวัน (1 แถว = 1 รายการอาหาร 1 มื้อ)
```
**โครงสร้างข้อมูลจริง:** ตาราง `nutrition` เก็บค่า **ต่อ 1 หน่วยเสิร์ฟ** (`ntt_*`) ส่วน `daily_nutrition` เก็บ **จำนวนหน่วยที่กิน** (`dntt_quantity`, `decimal(5,2)`) แล้วคูณเก็บผลลัพธ์ไว้เลย → ในเครื่องมือนี้จึงแยกเป็น "ช่องค่าต่อหน่วย" + "ตัวปรับจำนวน −/+ ทีละ 0.5" (ขั้นต่ำ 0.5 เพราะ backend บังคับ `binding:"required,gt=0"`) เหมือน UI แอปจริง

ตัวอย่าง (ทุกแถว qty=1): เช้า 450 + กลางวัน 650 + เย็น 500 + ว่าง 500 = **2,100 kcal**
ตัวอย่างคูณจำนวน: อาหาร 100 kcal / P10 / C20 / F5 กิน **2.5 หน่วย** → 250 kcal / P25 / C50 / F12.5

## [B] พลังงานที่ใช้ออกไป (Energy Out)

### B1. Baseline Expenditure

**ที่มา:** `calculator.go:31-35` `CalculateBaselineExpenditure`

```
Baseline = BMR × 1.2 (Sedentary Coefficient คงที่เสมอ — ไม่ใช่ Activity Factor จริงของผู้ใช้)
```
**เหตุผลที่ต้องคนละตัวกับ TDEE (ข้อ 0):** TDEE ใช้ AF จริงเพื่อหา "ควรกินเท่าไหร่" (A1) ส่วน Baseline ใช้ 1.2 คงที่เพื่อหา "พักนิ่งใช้ไปเท่าไหร่จริง" แล้วค่อยบวกพลังงานออกกำลังกายที่วัดได้จริงทีหลัง (B2+B3) — ถ้าใช้ AF จริงทั้งคู่จะนับพลังงานออกกำลังกายซ้ำสอง (**กฎเหล็กข้อ 4**)

ตัวอย่าง: 1648.75 × 1.2 = **1,978.5 kcal**

### B2. Cardio Burn

**ที่มา:** `workout_controller.go:1267-1280` `SaveCardioResult`

```
พลังงาน (ต่อกิจกรรม 1 ครั้ง) = (METs − 1) × น้ำหนักตัว(kg) × เวลา(ชม.)
```
METs **ต้องอ่านจากตาราง `cardio` (`cdo_mets`) เสมอ ห้าม hardcode** — ต่างกันตามชนิดกิจกรรม
หัก 1 MET ออกก่อนเก็บ (= NET, กันนับซ้ำกับ Baseline) · clamp กัน METs≤1 ติดลบ

**โครงสร้างข้อมูลจริง:** 1 วันอาจมีหลายกิจกรรม (`cardio_result` หลายแถวได้) → รวมทุกแถวเป็นยอดคาร์ดิโอวันนั้น

ตัวอย่าง (จ๊อกกิ้ง METs=8.3 — ตัวเลขตัวอย่างเท่านั้น ค่าจริงต้องอ่านจาก DB, 30 นาที, น้ำหนัก 70kg):
```
Net METs = 8.3 − 1 = 7.3
พลังงาน = 7.3 × 70 × (30/60) = 7.3×70×0.5 = 255.5 kcal
```

### B3. Weight Training — Smart Auto Calorie (6 ขั้นตอน, Step 1 = Dynamic Base MET ตั้งแต่ 2026-09-18)

**ที่มา:** `calculator.go` `CalculateWeightTrainingCalories` เรียกจาก `workout_controller.go` `SaveWorkoutResult` — รายละเอียดสูตรเต็ม → `../../CLAUDE.md` ข้อ 7[B-1]

**ค่าแต่ละตัวมาจากไหน (สำคัญ — ผู้ใช้จริงกรอกแค่ 2 อย่าง):**

| ค่า | มาจากไหน | ผู้ใช้ต้องทำอะไร |
|---|---|---|
| น้ำหนักที่ยก + จำนวนครั้ง (Reps) | ผู้ใช้กรอกตอนฝึกแต่ละเซต — Reps ยังใช้เลือก Base MET ต่อเซตด้วย (Step 1) | **กรอก** |
| เวลาพักต่อเซต (`wtrs_rest_seconds`) | นาฬิกาพักในแอปจับเอง (`_restSeconds`) ส่งขึ้น API จริงแล้ว (2026-09-18) — แถวเก่าก่อนหน้านั้นเป็น NULL ใช้ proxy ความหนาแน่นเฉลี่ยทั้งเซสชันแทน | ไม่ต้องทำ (จับอัตโนมัติ) |
| เวลารวมทั้งเซสชัน | นาฬิกาในแอปจับเอง (`_globalSeconds` เดินต่อเนื่องรวมเวลาพัก) | ไม่ต้องกด |
| น้ำหนักตัว | จากโปรไฟล์สมาชิก | **กรอกตอนสมัคร/แก้โปรไฟล์** |
| 1RM เดิมของท่านี้ | `getBestOneRepMax(mb_id, wet_id)` ค้นประวัติ `weight_training_result` ให้อัตโนมัติทุกครั้ง — **ไม่เจอประวัติ → ส่ง 0 → k_load = 1.00 กลาง ไม่เดา** | ไม่ต้องทำ |
| ตัวคูณ/เพดาน/clamp ทั้งหมด | ค่าคงที่ล็อกตามบทที่ 2 (`WeightTrainingCapMinutesPerSet` = 4.0, `METFloor` = 1.5, `METCeil` = 9.5) | แก้ไม่ได้ |

> ⚠️ `wet_base_met` (ตั้งไว้ต่อท่าในตาราง `weight_exercises`) **เลิกใช้ในการคำนวณตั้งแต่ 2026-09-08** —
> Step 1 ไม่อิงท่าฝึกเป็นตัวตั้งต้นอีกต่อไป เปลี่ยนเป็นเลือก MET ต่อเซตจาก Reps + เวลาพักแทน (ดูตารางด้านล่าง)
> ช่อง "1RM เดิม" ใน `main.html` เป็น **ช่องจำลองของเครื่องมือนี้เท่านั้น** ไว้ลองเคส "เคย/ไม่เคยฝึกท่านี้มาก่อน" — ในแอปจริงสมาชิกไม่เคยเห็นช่องนี้

**โครงสร้างข้อมูลจริง:** 1 เซสชัน = 1 ท่า แต่**หลายเซต** (`weight_training_result` insert เป็น array) — UX ปัจจุบัน 1 หน้าจอ = 1 ท่า

**[Step 1] Dynamic Base MET ต่อเซต** — เลือกจากตาราง lookup ต่อไปนี้ แล้วเฉลี่ยเป็น Session Base MET
(เฉพาะ 3 แถวแรกมี entry ตรงใน Compendium of Physical Activities แถว "Reps > 15" เป็นค่าประมาณที่ผู้วิจัย
ตีความขยายเอง ไม่ใช่ Compendium ระบุไว้ตรงๆ):

| พักระหว่างเซต | Reps | MET |
|---|---|---|
| < 30 วินาที | ใดๆ | 8.0 |
| 30–60 วินาที | ใดๆ | 4.3 |
| ≥ 60 วินาที | < 8 | 6.0 |
| ≥ 60 วินาที | 8–15 | 3.5 |
| ≥ 60 วินาที | > 15 | 3.5 (ส่วนขยาย) |

**ตัวอย่างเดินสูตร (กรณี fallback — ไม่ทราบเวลาพักรายเซต):** ท่าสควอท · 4 เซต × 10 ครั้ง × 60kg ทุกเซต ·
รวมเวลา 480 วินาที · น้ำหนักตัว 70kg · ประวัติ 1RM ก่อนหน้า = ยก 65kg×8ครั้ง · **สมมติเป็นแถวเก่าที่
`wtrs_rest_seconds` เป็น NULL** (แอปจริงตอนนี้ส่งเวลาพักจริงมาแล้ว ตัวอย่างนี้โชว์เส้นทาง fallback) → ใช้ proxy

```
actualMinutes = 480/60 = 8.0 นาที
cap = จำนวนเซต × 4 นาที = 4×4 = 16 นาที
cappedMinutes = min(8.0, 16) = 8.0 นาที
density = cappedMinutes / จำนวนเซต = 8.0/4 = 2.0 นาที/เซต

densityProxySeconds = 2.0×60 = 120 วินาที (proxy แทนเวลาพักรายเซตจริง — ทุกเซตเท่ากันหมด)
→ 120 วินาที ≥ 60 และ Reps=10 (อยู่ในช่วง 8-15) → MET ต่อเซต = 3.5 ทุกเซต

Session Base MET = ค่าเฉลี่ย MET ทั้ง 4 เซต = 3.5
```

**Step 2 — Density → k_density**
```
k_density: density ≤ 1.0        → 1.20
           1.0 < density < 3.0  → 1.20 − 0.15×(density−1.0)
           density ≥ 3.0        → 0.90

→ density=2.0 อยู่ช่วงกลาง: k_density = 1.20 − 0.15×(2.0−1.0) = 1.20−0.15 = 1.05
```

**Step 3 — %1RM เฉลี่ย (RI) → k_load**
```
1RM ก่อนหน้า = 65 × (1 + 8/30) = 65×1.26667 = 82.33 kg
RI = น้ำหนักที่ยก / 1RM = 60/82.33 = 0.7288 (72.88%)

k_load: RI < 50%       → 0.90 (เบา, level=1)
        50% ≤ RI < 70%  → 1.00 (กลาง, level=2)
        RI ≥ 70%        → 1.10 (หนัก, level=3)

→ RI=72.88% ≥70% : k_load = 1.10, level=3(หนัก)
ไม่มีประวัติ 1RM หรือทุกเซต bodyweight (weight=0) → k_load=1.00 กลาง (ไม่เดา)
```

**Step 4 — Final MET + clamp**
```
Final MET = Session Base MET × k_load × k_density
          = 3.5 × 1.10 × 1.05 = 4.0425
clamp ให้อยู่ [1.5, 9.5] เสมอ → 4.0425 ไม่ชนขอบ
```

**Step 5 — พลังงาน (NET)**
```
effectiveHours = cappedMinutes/60 = 8/60 = 0.13333 ชม.
Kcal = (Final MET−1) × น้ำหนักตัว × effectiveHours
     = 3.0425 × 70 × 0.13333 ≈ 28.40 kcal (รวมเซสชัน)
```

**Step 6 — กระจายลงต่อเซต**
```
Kcal/เซต = TotalKcal / จำนวนเซต = 28.40/4 ≈ 7.10 kcal
```

**เครื่องมือช่วยในโมดูลเดียวกัน (มาจากตารางเซตเดียวกัน):**
```
Estimated 1RM (เซสชันนี้) = max( weight × (1+reps/30) )  ต่อเซต  → 60×(1+10/30) = 80.00 kg
Training Volume            = Σ(weight × reps)  ทุกเซต        → 60×10×4 = 2,400 kg
```
(ทั้งสองอนุญาตให้ Dart คำนวณ preview ได้ ไม่บันทึก DB — กฎเหล็กข้อ 2)
